# Security review: September 2026

This is a source review and hardening pass, not an independent penetration test or a claim that Web matches the security coverage of Safari or Chrome. WebKit and macOS provide the underlying web sandbox and certificate trust evaluation. Keep macOS updated.

## Changes in this revision

- **Native message origins.** The shared bridge validator rejects subframes, opaque/local origins and origins that differ from the current top-level page. It bounds message fields and values without rewriting their content. Credential messages use a separate WebKit content world and require an exact HTTPS origin; a page-supplied hostname is never used as authority. The substring credential matching and automatic password capture on form submission are removed. Existing credential suggestion UI was incomplete, so the settings no longer advertise a password manager.
- **Credential storage.** Password metadata, including account names and notes, migrates from UserDefaults into the Keychain after a successful write. Encryption-key lookup failures fail closed instead of generating an unusable replacement key. Credential updates no longer delete the old record before a new write succeeds. Existing credentials are retained; migration failure leaves the old metadata available for a later attempt.
- **TLS.** Certificate evaluation explicitly binds an SSL policy to the challenged hostname. An invalid trust result or pin mismatch cannot be bypassed through the old persistent host allowlist. Old blanket exceptions are discarded. Sample certificate pins are removed; macOS trust remains active. Certificate console diagnostics no longer include hostnames.
- **Network privacy.** ATS permits HTTP in WebKit for general browsing; the separate native-media exception is removed. Google Safe Browsing's existing lookup endpoint sends full URLs, despite previous claims that it sent hashes. Remote lookups now require a separate opt-in, default off, and are skipped for private tabs and private downloads. The settings disclose this behavior. The DNS toggle is removed because setting environment variables did not control WebKit's DNS resolver.
- **Private browsing.** Session cleanup now targets the same nonpersistent WebKit store used by private tabs. The last private-tab close replaces that store. Private pages are excluded from shared AI extraction/cache and the shared favicon fetch/cache path. Downloads initiated from private WebViews skip persistent download history. The incomplete JavaScript overrides of cookies, canvas and WebRTC are removed; private websites can use temporary cookies and storage normally.
- **Downloads.** Server filenames are reduced to a single bounded filename with path separators and direction-control characters removed. Attachments and unsupported content hand off through WKDownload, retaining the original request rather than fetching the URL again. Native downloads and URLSession fallback files use owned staging storage; fallback temporary files are moved there before the delegate callback returns. Hashing streams in bounded chunks off the main actor. When quarantine is enabled, it is applied before moving a file to its final destination, and a failure prevents that move. Quarantine uses the native macOS URL resource API. Private downloads omit source URLs and remove inherited Spotlight origin metadata. Fresh installations enable the scan, warning and quarantine defaults. Failed, skipped or timed-out scans are no longer marked validated.
- **Settings and diagnostics.** Settings expose working controls instead of disconnected promises about DNS, fingerprinting, process isolation, hibernation and runtime protection. The misleading all-data reset is replaced by scoped website-data/history actions. History in AI context defaults off. Device names and several account/session identifiers are removed from security diagnostics. Web Inspector is opt-in for new tabs. JIT diagnostics no longer pretend that disabling page JavaScript tests a signing entitlement.

## Verified here

`BrowserSecurityTests` covers credential domain spoofing, HTTP downgrade/port mismatch, subframe and stale-origin messages, path traversal, direction-control spoofing and filename bounds. All five passed in the 65-test application suite. Download policy, file lifecycle and type classification have separate regression tests. The Release build passed, and an installed-app attachment check preserved its exact bytes and native quarantine attribute. [Validation details](validation.md) record the tested scope.

## Remaining boundaries

- A content world isolates JavaScript variables and handlers; DOM changes remain visible to the website. Most noncredential helper scripts still run in the page world. Their messages are untrusted diagnostics, not evidence of blocking or an authorization mechanism. The legacy CSP nonce wrapper does not enforce a site's CSP or prevent XSS.
- Private browsing is not anonymity. Network operators, websites, the operating system and explicitly downloaded files can retain evidence. Existing diagnostic services and OS logs need a broader end-to-end private-session audit. Regular and private credentials are intentionally not shared through the browser's password service.
- Download heuristics and the legacy scanner are not a maintained antivirus engine. A clean result is not proof a file is safe. Reputation checks may be unavailable, including without an API key. User-enabled URL checks send URLs to Google; local threat/override caches also need lifecycle review.
- The host `allow-jit` entitlement was removed after local MLX generation and WebKit navigation ran in a signed Release build without it. No unsigned-memory entitlement is added.
- Passkeys, extension permissions, authenticated download integration coverage, per-site camera/microphone controls, credential filling UI, crash-log redaction and adversarial integration tests need further work. The removed security dashboards did not implement these capabilities.
- This change does not rewrite Git history or change the identity embedded in an Apple Developer signing certificate. Those are separate release/privacy decisions.

## Platform references

Apple documents [WKContentWorld isolation and shared DOM access](https://developer.apple.com/documentation/webkit/wkcontentworld), [SSL hostname policies](https://developer.apple.com/documentation/security/secpolicycreatessl(_:_:)) and [setting trust policies](https://developer.apple.com/documentation/security/sectrustsetpolicies(_:_:)). These APIs support the implemented boundaries; they do not constitute an audit of the application.
